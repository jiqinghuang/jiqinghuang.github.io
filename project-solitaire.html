项目简介Overview

把「这局是不是死局」从模糊的挫败感，变成可判定、可解释的结论Turning "is this deal dead?" from vague frustration into a decidable, explainable verdict

>_

为谁而做Who It Is For

给怀念 Windows 纸牌的人，也给那些「走了半小时发现赢不了、却不知道是自己的问题还是牌的问题」的玩家。浏览器打开即玩，零安装。For anyone nostalgic for Windows Solitaire — and for players who spend half an hour only to wonder whether they lost or the deal was simply unwinnable. Open the page and play, nothing to install.

?

为什么做它Why I Built It

Klondike 不是每局都赢——翻一张约八成可胜，翻三张不到两成。多数游戏对此闭口不谈，把「无解」变成玩家的自我怀疑。这个项目把它摊开讲清楚。Not every Klondike deal is winnable — roughly 80% with draw-one, under 20% with draw-three. Most implementations stay silent about this, leaving players to blame themselves. This one spells it out.

✓

不谎报No False Claims

求解器只给三种结论：还能赢、已死局、暂不确定。搜索超限就老实说「搜不出来」，绝不含糊地判你输，也不假装能赢。The solver answers with exactly three verdicts: winnable, dead, or undetermined. When the search budget runs out it says so plainly — it never declares a loss it cannot prove, nor a win it cannot reach.

完整规则Complete Rules

七列牌阵红黑交替、空列只接 K、四门花色 A→K 收牌；翻一张 / 翻三张两种抽牌模式，废牌堆回收严格保持物理翻堆顺序。Seven tableau columns alternating colors, empty columns accept kings only, four foundations building A→K. Both draw-one and draw-three modes, with waste recycling preserving true physical flip order.

死局可判定Decidable Dead Ends

每次走子后快速检查局面是否还能推进；确认无解时直接弹面板说明「为什么」——哪张牌被埋住、在等哪张牌、收牌卡在第几步、腾不出空列。Every move triggers a quick check for remaining progress. On a confirmed dead end a panel explains why — which card is buried, what it is waiting for, where the foundations stalled, why no column can be freed.

必胜路线Winning Line

「分析局面」跑带转移表的 DFS，判定可胜时从搜索记录里回溯出一条完整的必胜路线，并直接给出第一步该怎么走。"Analyze position" runs a transposition-table DFS; when the deal is winnable it backtracks a complete winning line from the search and tells you the exact first move.

工程实现Implementation

引擎与界面彻底分离，规则全部可被 Node 直接测试Engine fully decoupled from the UI — every rule testable straight from Node

引擎零 DOMDOM-Free Engine

engine / solver 不知道 DOM 存在，发牌、叠放、翻牌、撤销、求解全部可在 Node 里直接跑；界面层只负责渲染与指针事件。The engine and solver know nothing about the DOM — dealing, stacking, drawing, undo and solving all run directly in Node. The UI layer only renders and handles pointer events.

求解器对拍Solver Cross-Check

求解器有独立于引擎的走法生成（便于剪枝），正确性靠与引擎逐状态对拍保证：在随机牌局上枚举双方全部合法走法，必须完全一致。The solver generates moves independently of the engine (for pruning), and correctness is guaranteed by cross-checking: on random positions both sides enumerate every legal move and must agree exactly.

撤销即反向操作Inverse-Operation Undo

每步不克隆整盘 52 张牌，只记录「从哪到哪、翻开了哪张、元状态」，每条几十字节；自动翻牌、回收与胜负状态一起精确回滚。Rather than cloning all 52 cards per step, each entry records only where cards moved from and to, which card was revealed, and the meta state — tens of bytes each. Auto-reveals, recycling and win state all roll back precisely.

响应式牌宽Responsive Card Width

牌宽用 clamp() 随视口伸缩，窗口大时牌也大（1920px 下牌桌占 54% 宽），小屏自动缩到 30px 下限；27 种视口宽度上验证不出现横向滚动条。Card width scales with the viewport via clamp() — the board takes 54% of a 1920px screen and shrinks to a 30px floor on small screens. Verified across 27 viewport widths that no horizontal scrollbar ever appears.

配色按色彩科学Scientifically Derived Colors

红黑交替是游戏规则，颜色本身就是信息。四色按 OKLCh 构造：两个红都在红色区（色相 <36°），四个花色对牌面的对比度全部达到 WCAG AA，两个黑同色相仅差明度。Red/black alternation is a game rule, so color itself carries information. All four suits are built in OKLCh: both reds sit in the red hue range (<36°), every suit meets WCAG AA contrast against the card face, and both blacks share one hue, differing only in lightness.

CI 护栏CI Guards

GitHub Actions 每次推送执行类型检查、273 条测试，并校验 dist/ 与 src/ 逐字节一致——改了源码忘编译、或漏提交产物都过不了。配色与布局另有专门校验，改坏了 CI 会直接失败。GitHub Actions runs typecheck and all 273 tests on every push, and verifies that dist/ matches src/ byte for byte — a forgotten build cannot ship. Colors and layout have dedicated checks, so breaking either fails CI outright.

独立完成规则引擎、求解器与死局诊断、界面与交互开发（指针拖动、点选、双击、键盘、触屏）、测试体系与 CI 建设，以及配色与响应式布局的量化校验。 Independently built the rules engine, the solver and dead-end diagnosis, the UI and interactions (pointer drag, tap-to-select, double-click, keyboard, touch), the full test suite and CI, plus the quantitative checks for color and responsive layout.
